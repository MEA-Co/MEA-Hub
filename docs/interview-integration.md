# 모의 면접 구현 및 실행 안내

갱신일: 2026-10-29 · 활동 질문의 맥락 선택·지원학과·전공 질문 반영

## 학생 화면과 입력

면접 화면은 `/interview` 안의 **활동 입력 / 면접** 두 탭으로 구성됩니다. 검정·노랑·회색 디자인은 면접 화면에만 적용하며, 로고·상단 메뉴·결과 버튼을 통한 다른 허브 영역 이동은 제공하지 않습니다. 기존 홈의 생기부 업로드 입구는 숨겼고 `/record`는 `/interview`로 이동합니다. Core의 기존 `/api/record`는 유지하지만 이 면접 흐름에서는 호출하지 않습니다.

활동 입력 화면의 순서는 원문·개인정보 제외 동의 → 지원학과 → 활동 정리 도우미 → 준비 TXT 보관/가져오기 → 기본 펼침인 선택 특이사항 → 활동 목록입니다. 미동의 상태에서 ‘면접 설정으로 이동’이나 상단 면접 탭을 선택하면 동의 항목을 강조하고 스크롤·포커스로 안내합니다. 키보드 탭 이동에도 같은 기준을 적용합니다.

새 Hub는 지원학과를 **1~100자 자유 입력**으로 받습니다. 시작 시 빈 값이나 개인정보가 포함된 값이면 활동 입력 탭의 해당 항목으로 안내합니다. 학과명은 질문의 맥락이며 학생의 수준·전공 적합성 판정 근거가 아닙니다.

| 활동 입력       | 범위                                                   |
| --------------- | ------------------------------------------------------ |
| 학년            | 1·2·3학년                                              |
| 영역/과목       | 자율·동아리·진로·교과 세특·주요 활동, 과목명 선택 입력 |
| 주제(제목)      | 필수, 최대 100자                                       |
| 핵심내용        | 역할·과정 등 사실, 면접 시작에는 20~2,000자            |
| 느낀점/알게된점 | 선택, 빈칸·한 글자도 허용, 최대 1,000자                |

면접 시작에는 **창체·세특·주요 활동 합계 10개 이상**, 최대 60개가 필요합니다. 영역별 필수 개수는 없으며 핵심내용과 느낀점 전체 합계는 60,000자 이내입니다. 빈 느낀점은 미입력일 뿐이며 배움이나 성찰이 없다고 추정하지 않습니다.

성적 관련 상황은 최대 3개까지 과목 또는 학년·학기와 짧은 설명으로, 진로 변경은 이전·현재 관심 분야와 선택 설명으로 입력합니다. 사용하지 않는 그룹은 면접 요청에 보내지 않습니다. 이 항목은 질문 후보용 선택 정보이며 등급·점수나 원본 생기부는 요구하지 않습니다.

작성 내용과 면접 중 답변은 탭을 이동해도 유지됩니다. 진행 중에는 지원학과·활동·특이사항 편집을 막으며, 면접 시작 시 복사한 지원학과·특이사항을 답변·종료·재시도 요청에도 사용합니다. 새로고침 후 복원하는 자동 저장은 없습니다.

## 준비 TXT와 결과 TXT

준비 파일은 JSON에 확장자만 바꾼 형식이 아니라 한국어 필드명과 활동 구분자를 쓰는 TXT입니다. 첫 줄은 `MEA 면접 준비 TXT v1`이며, 문자열의 각 줄은 `| `로 시작합니다.

```text
MEA 면접 준비 TXT v1

[지원 정보]
지원학과:
| 컴퓨터공학과
[/지원 정보]

[활동]
학년: 2
영역: 교과 세특
과목:
| 정보
주제(제목):
| 관찰 자료의 분류 기준 비교
핵심내용:
| 제가 같은 자료를 분류하고 기준에 따라 결과가 달라지는 이유를 비교했습니다.
느낀점/알게된점:
|
[/활동]
```

`exportPreparationText(activities, circumstancesDraft?, targetMajor?)`는 작성 중 활동과 선택 정보를 보관합니다. 미완성·10개 미만 활동도 저장할 수 있고, 내보낸 파일에는 활동 식별자도 포함됩니다. 여러 줄·콜론·구분자·역슬래시·탭 등의 내용은 형식에 맞춰 보존합니다. `importPreparationText()`는 전체 형식·개수·길이·중복·원문 및 명백한 개인정보 표지를 확인한 뒤 한 번에 적용하므로 실패 시 현재 입력을 일부만 교체하지 않습니다.

- `[지원 정보]`가 없으면 현재 지원학과를 유지하고, 있으면 해당 값을 반영합니다.
- `[특이사항]`이 없으면 현재 특이사항을 유지합니다. 있으면 사용 여부, 선택값, 비활성·미완성 초안까지 반영합니다.
- 두 선택 섹션이 없는 이전 준비 TXT도 가져올 수 있습니다. 식별자나 느낀점이 없는 활동은 각각 새 식별자·빈 느낀점으로 처리합니다.
- 기존 JSON 활동 변환 함수와 저장 API는 호환을 위해 남아 있지만, 현재 화면의 가져오기·보관 기능은 TXT만 노출합니다.

결과 TXT는 질문·답변·질문 유형·한 문단 피드백과 시작 당시 지원학과를 보관합니다. 준비 TXT와 용도가 다르므로 결과 TXT를 준비 파일로 가져오지는 않습니다. 원본 PDF·이미지·생기부 업로드와 결과 JSON 버튼은 제공하지 않습니다. 원문·개인정보 검사는 모든 민감정보를 완벽히 탐지하는 분류기는 아닙니다.

## 질문 선택과 진행

시간은 **3~20분**, 기본 10분입니다. 남은 시간 표시, 도입 질문 사용, 마지막 한마디를 선택합니다. 첫 질문이 완성되면 타이머가 시작되고, 숨김 설정과 무관하게 마지막 1분에는 알림이 나타납니다. 마지막 한마디를 선택하면 마지막 1분의 다음 질문으로 우선 제시합니다. 시간 만료·수동 종료·마지막 답변 제출 시 결과를 정리하며 작성 중 답변과 미답변 질문도 기록합니다.

### 도입 질문

새 Hub는 `ask_intro`만 보냅니다. 켜면 서버가 자기소개·지원동기·진로/학습 계획 중 하나를 고르며 첫 문장은 서버 템플릿입니다. 답변에서 자발적으로 말한 구체적인 선택·성과 주장에 추가 확인 가치가 있을 때만 최대 두 번 후속 질문합니다. 단순 관심·감상, 충분한 설명, 모름·경험 없음·철회라면 활동 질문으로 넘어갑니다. 도입 후속 프롬프트에는 활동 목록을 넣지 않습니다.

### 활동 질문: 선택과 생성을 한 번에

실제 AI 모드의 활동 질문은 **별도 분류 호출 없이 구조화된 모델 호출 한 번**에서 경로·관점·질문을 함께 결정합니다. 내부 응답은 `route=current|next`, 기존 12개 관점 중 `focus`, 질문 문장 `question` 세 필드뿐입니다.

서버는 현재 활동과 전환 후보를 최대 두 개만 제공합니다. 모델은 허용된 후보·관점 안에서 선택하고, 활동 ID·출처·깊이·시간 상한은 서버가 확정합니다. 현재 질문의 확인 목적에 직접 답했고 중요한 미해결 부분이 없다면 다음으로 이동합니다. 따라서 같은 활동의 후속은 **0~2개**이며 두 개를 채우지 않습니다. 짧은 완결 답변도 넘어갈 수 있고 길이나 전문용어 수로 충분함·학생 수준을 판정하지 않습니다.

새 활동의 첫 관점도 카테고리에 고정하지 않습니다. 실제로 언급한 개념, 본인의 선택·역할, 검증 방법, 판단 과정, 성찰 단서에서 확인할 가치가 있는 하나를 고릅니다. 교과 세특이라는 이유만으로 개념을 묻거나 대학 수준의 정의·증명을 강요하지 않습니다. 빈 느낀점을 지어내거나 모든 활동을 지원학과와 억지로 연결하지 않습니다.

활동은 적게 다룬 활동·영역·학년을 우선합니다. 그 세 기준이 동률인 후보 안에서만 일부 순서에 학과 관련 활동을 우선하고, 다른 순서에는 기존 순서를 사용합니다. 관련 단어 하나 때문에 이미 많이 다룬 활동을 반복하지 않습니다. 명칭·키워드 연결은 선택 보조 단서이며 적합성 평가가 아닙니다.

서버는 실제 연속 이력으로 후속 상한을 복원하므로 클라이언트가 depth를 바꿔도 두 번을 넘길 수 없습니다. 남은 90초에는 짧은 핵심 확인 관점만 허용하며, 1분·마지막 한마디와 종료 조건은 모델 선택보다 우선합니다. 활동을 일찍 끝내더라도 해당 전환 경계에서 기존 일반·특이사항·전공 질문의 안전 기준을 유지합니다.

구조화 응답은 완성 후 검증하여 최종 `question`으로 보냅니다. 이 경로는 준비 상태와 SSE keepalive를 유지하지만 원시 JSON이나 중간 토큰은 화면에 표시하지 않습니다. 첫 글자는 응답 완성까지 기다리며, 별도의 가짜 타자 효과는 넣지 않습니다. 잘못된 JSON·거절·중단·허용되지 않은 경로/관점은 답변을 유지한 재시도 오류로 처리하고 자동 보정 모델 호출은 추가하지 않습니다. 새 활동 제목이 빠진 질문은 최종 문장을 안전한 해당 활동 템플릿으로 대체합니다.

### 일반 경험·전공·선택 특이사항

활동 답변이 실제로 세 개 이상 제출됐고 남은 시간이 120초 이상인 전환 지점에서 다른 질문을 섞습니다. 연속 삽입을 피하고 모든 후보를 반드시 질문하지는 않습니다.

| 질문군    | 선택·후속 규칙                                                                                                                                                                |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 일반 경험 | 의미 있었던 활동·실패 경험·협력/갈등 해결·리더십의 네 유형. 입력 목록 밖 실제 경험도 허용하며 첫 문장은 서버 템플릿. 답변이 충분하면 전환, 미해결 단서가 있을 때만 후속 0~1개 |
| 전공      | `foundation` 또는 `issue`. 일반 경험과 **합쳐서 최대 두 root 주제**, 같은 전공 주제 재질문 방지. 새 한계·확인되지 않은 자발적 주장 등에 필요할 때만 후속 최대 1개             |
| 특이사항  | 관련 과목·이전/현재 관심 분야를 우선하거나 표집. 같은 항목 반복·연속 삽입 금지, 일반/전공과 별도의 최대 2개 한도                                                              |

일반 경험과 전공 후속은 미해결 한계·단정·근거 없는 자발적 선택을 보수적인 단서로 사용하며, 남은 시간이 90초 이하면 생략합니다. 설명이 완결됐거나 모름·거절을 밝히면 질문 수를 채우지 않고 넘어갑니다.

전공 root는 해당 전환 기회 중 일부에서 선택하며 유형을 학생이 따로 고르는 UI는 없습니다. 컴퓨터·공학·생명보건·경영경제·인문사회·디자인의 작은 주제 묶음을 사용합니다. 기초는 알고리즘 등을 자신의 말이나 익숙한 예로 설명하는 질문이고, 현안은 확인한 공식 자료의 넓은 쟁점만 사용합니다. 등록되지 않은 학과는 학생이 고른 기초 개념이나 정보 확인 기준을 묻는 안전한 범위로 제한합니다.

`major.py`의 자료는 NIST·IEA·WHO·St. Louis Fed·UNESCO·W3C 공식 출처를 2026-10-29에 확인했으며 URL·확인일을 내부 문맥에 전달합니다. 실행 중 뉴스 검색은 하지 않고 ‘최신 뉴스’·특정 대학 교육과정·입력에 없는 사건이나 통계를 사실로 만들지 않습니다. 전공 질문의 구체적 문장은 해당 근거와 답변 안에서 모델이 생성합니다.

현재 모름·거절·철회는 존중해 다음으로 이동합니다. 과거의 모름을 실제 행동으로 해결했거나 정정·이중부정 뒤 현재 설명을 이어간 경우는 그 실제 설명을 보존하고, 미래 계획만으로 과거 경험이 있었다고 해석하지 않습니다. 전환 시 `Question.transition`으로 ‘그럼 다음 질문으로 넘어갈게요.’를 질문과 분리해 표시할 수 있습니다. 안내는 답변 이력이나 결과의 질문 문장에 섞지 않습니다.

## API·이력 호환

요청에는 설정·활동·이력·경과 시간·동의와 선택 `circumstances`, `target_major`를 보냅니다. `target_major`는 Core에서 생략/`null`을 허용하는 1~100자 문자열이므로 이전 소비자도 사용할 수 있습니다. 새 Hub는 시작에 학과 입력을 요구하고, 유효한 시작 값을 이후 요청에도 고정해 전달합니다.

`ask_intro` 기본값은 false이며 예전 `ask_self_introduction`·`ask_motivation`도 기본 false로 받아 호환합니다. 새 `ask_intro=true`가 세 도입 중 하나를 선택하고, 꺼져 있으면 기존 필드가 지정한 질문 경로를 사용할 수 있습니다. `kind`는 `self_introduction`, `motivation`, `learning_plan`, `activity`, `final_remarks`입니다.

선택적인 `strategy`는 다음과 같이 질문과 제출 이력에 유지됩니다. 일반·특이사항·전공의 공통 `kind`는 `activity`입니다.

| source       | 식별 필드                         | 깊이 |
| ------------ | --------------------------------- | ---- |
| activity     | activity_id                       | 0~2  |
| intro        | root의 kind 유지, 다른 ID 없음    | 0~2  |
| general      | general_topic                     | 0~1  |
| circumstance | circumstance_id                   | 0    |
| major        | major_topic=foundation 또는 issue | 0~1  |

`focus`, `version`, `mix_seed`도 보존합니다. `mix_seed`는 공개 난수이며 후보·주제 표집에 사용합니다. 이미 받은 전략의 이력·횟수는 재현하지만 모델의 의미 선택이나 문장까지 동일하게 만드는 seed는 아닙니다. 전략이 없는 구형 이력이나 알 수 없는 활동 ID는 사실을 추정하지 않고 분산용 가상 슬롯만 계산합니다.

활동 구조화 호출에는 최신 질문·답변 전문과 최대 두 후보를 주고, 이전 문답 문맥은 예산 안에서 줄입니다. 다른 질문·평가 문맥도 앞·끝과 최근 정정을 우선해 제한하지만 결과의 전체 원문은 보존합니다. 긴 문맥의 중간은 생략될 수 있습니다.

피드백은 실제 제출한 답변만 근거로 탐구 이해·본인 역할·논리/대안·성찰·협업·관심 확장을 살펴보고 4~6문장 한 문단을 목표로 합니다. 미답변·선택 항목 미입력과 역량 부족을 구분합니다. 점수·합격 가능성·학교 공식 평가표·음성·태도·외모는 판정하지 않습니다. ‘피드백 기준’에서 같은 기준을 확인할 수 있습니다.

## 채팅·음성·저장과 서버 연결

채팅은 항상 사용할 수 있습니다. CLOVA 실시간 게이트웨이를 설정한 경우 AudioWorklet이 16kHz·모노·16비트 PCM을 약 100ms 단위로 Core WebSocket에 전송하고 녹음 중 문장을 표시합니다. 최대 녹음은 2분이며, 완료 시 마지막 조각과 최종 문장을 확인한 후 학생이 직접 수정·제출합니다. 기존 작성 답변과 음성 부분은 구분해 중복 없이 갱신합니다. 오류·취소에도 인식한 내용을 남기며 탭 이동·종료 시 마이크와 연결을 정리합니다.

AudioWorklet 미지원 또는 HTTPS 파일 인식만 설정된 경우 녹음 완료 후 WAV 전송으로 대체하고 이를 안내합니다. 음성 실패 후에도 채팅은 사용할 수 있습니다. 음성 출력은 제공하지 않습니다.

```text
Hub /interview → Hub /api/interview/stream → Core /api/interview/stream → OpenAI
브라우저 AudioWorklet → Core /api/interview/speech (WebSocket) → CLOVA gRPC
Hub /api/interview/transcribe → Core /api/interview/transcribe (파일 인식 대체)
Hub /api/interview/capabilities → Core 기능 설정
```

현재 화면은 DB 저장 API를 호출하지 않습니다. 이전 `/api/interview/activities` GET/PUT는 호환을 위해 유지하며 DB가 설정된 경우 명시적 PUT만 초안을 저장합니다. 소유 토큰 해시와 revision 비교를 사용하고 다른 DB 테이블은 수정하지 않습니다. 로그인·기기 간 복구·면접 대화/결과 자동 저장은 없습니다. DB가 없으면 준비 TXT만으로 사용할 수 있습니다.

## 설정·실행·배포 상태

| 위치 | 변수                                              | 용도                                                     |
| ---- | ------------------------------------------------- | -------------------------------------------------------- |
| Hub  | CORE_API_URL                                      | Core 기본 주소, 기존 NEXT_PUBLIC_BACKEND_ORIGIN보다 우선 |
| Hub  | INTERVIEW_SPEECH_WS_URL                           | 선택적인 브라우저 공개 WebSocket 주소                    |
| Core | OPENAI_API_KEY                                    | 실제 질문·평가에 필요                                    |
| Core | INTERVIEW_MODEL                                   | 기본 gpt-6-luna, 해당 모델은 reasoning_effort=none       |
| Core | INTERVIEW_DEMO_MODE=true                          | 실제 AI 호출 없는 명시적 예시 모드                       |
| Core | ALLOWED_ORIGINS                                   | 허용 Hub Origin 목록, 쉼표 구분                          |
| Core | CLOVA_SPEECH_INVOKE_URL / CLOVA_SPEECH_SECRET_KEY | 음성 설정, 이전 CLOVA_HOST / CLOVA_SECRET_KEY도 지원     |
| Core | INTERVIEW_DATABASE_URL / DATABASE_URL             | 선택적인 기존 활동 저장 API용 DB                         |

Core는 로컬 `.env`를 읽지만 파일이나 키를 브라우저에 전달하지 않습니다. 저장소의 SAM 배포 설정은 GitHub repository secret `OPENAI_API_KEY`를 빌드 전 확인하고, 배포 단계의 제한된 임시 설정 파일에서 CloudFormation `OpenAIApiKey` NoEcho parameter를 거쳐 Lambda 환경에 전달합니다. 키를 이미지·소스·Metadata·Output에 넣지 않으며 임시 설정·로그는 종료 시 정리합니다. 실제 secret 등록과 운영 환경 주입 여부는 별도 운영 확인 사항입니다. CLOVA·DB 설정은 이 키 연결과 별개입니다.

기존 Lambda 경로는 HTTP API Gateway + Mangum + 30초 제한으로 응답을 모아 반환합니다. 실시간 응답에는 Uvicorn 서버 또는 별도 응답 스트리밍 배포가 필요합니다. 실시간 음성도 지속적인 WebSocket 업그레이드와 HTTPS Hub에서 WSS가 필요하며, 공개 주소·Origin·연결 유지 시간을 운영 환경에 맞춰 제공해야 합니다. Hub 스트림 프록시는 실행 설정 120초·연결 제한 100초, DB 프록시는 20초 제한입니다.

```sh
# Core
.venv/bin/python -m pip install -e '.[dev]'
ALLOWED_ORIGINS=http://localhost:3001,http://127.0.0.1:3001 .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --reload --port 8000

# Hub: 별도 터미널
CORE_API_URL=http://127.0.0.1:8000 npm run dev -- --hostname 127.0.0.1 --port 3001
```

이번 활동·전공 정책 변경은 로컬 구현·검증 상태입니다. 이 변경의 푸시·운영 배포나 실제 키 등록은 수행하지 않았습니다. 로컬 테스트 통과가 운영의 키·주소·스트리밍 지원을 보장하지 않습니다.

## 검증

현재 변경에 대한 자동 회귀는 **Core 402개, Hub 132개**가 통과했습니다. Core는 구조화 1회 호출·충분 답변 조기 전환·후속 상한·허용 후보/관점·잘못된 JSON/거절·문맥 예산·정정·모름·전환 안내·공동 root 한도·학과 관련성 분산·공식 근거 문맥을 확인합니다. Hub는 지원학과 필수/개인정보 검증, 준비 TXT의 지원 정보·선택 섹션 왕복과 이전 파일 호환, snapshot·재시도·전략 보존, 전환 안내와 답변/결과의 분리, 컴포넌트 행동을 확인합니다.

```sh
# Core
.venv/bin/python -m pytest -q
.venv/bin/ruff check app/interview app/main.py tests

# Hub
npm run test:interview
npm run lint:interview
npm run typecheck
npm run build
```

자동 회귀에는 합성 입력과 가짜 모델/서버 응답을 사용합니다. 별도로 로컬 서버에서 실제 모델의 구조화 질문 네 경우와 Hub의 준비 TXT 보존·전공 전략 왕복 흐름을 확인했습니다. 이 확인은 실제 음성·운영 배포 검증이나 모든 문답의 품질 보장을 뜻하지 않습니다. 면접 관련 lint/type/build는 별도 확인하며 전체 Hub lint의 다른 기능 오류와 섞지 않습니다.
